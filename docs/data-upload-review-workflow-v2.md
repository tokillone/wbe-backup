# 数据上传与审核流程 V2

## 1. 设计依据

本流程以 `WBE汇总表7.22.xlsx` 和 `WBE汇总表7.28.xlsx` 为参考。两版均包含 6 张工作表：

| 工作表 | 7.22 | 7.28 | 责任归属 |
| --- | ---: | ---: | --- |
| 数据表 | 58 列 | 59 列 | 普通上传者提交 |
| 文献基础信息 | 5 列 | 5 列 | 审核人员整理 |
| 点位关联表 | 12 列 | 12 列 | 审核人员整理 |
| 药物疾病ICD11映射 | 28 列 | 29 列 | 审核人员整理并复核 |
| 采样方法统一审计 | 17 列 | 17 列 | 审核人员整理并复核 |
| 核心标记物优先级识别 | 54 列 | 99 列 | 由整理脚本生成，审核人员复核 |

“核心标记物优先级识别”列数变化很大，且包含统计分位数、评分和排名，不应交给普通上传者手工填写。

## 2. 文件与责任边界

### 2.1 普通上传者：提交文件

- 只要求一个名为“数据表”的业务工作表。
- 表头采用 7.28 版 59 个字段，同时兼容缺少“目标物质细类”的 7.22 版。
- 可以包含“填写说明”等非业务工作表；系统只读取“数据表”。
- 文件通过结构和逐行校验后进入“待初审”，不能直接入库。
- 原文件永久保留在该批次下，后续整理包不得覆盖原文件。

### 2.2 审核人员：完整整理包

初审确认原始数据可继续整理后，由审核人员在批次中上传完整整理包。完整整理包必须包含上述 6 张工作表。

- “数据表”必须覆盖本批次提交文件中的全部业务行。
- “文献基础信息”“点位关联表”“药物疾病ICD11映射”是入库数据。
- “采样方法统一审计”“核心标记物优先级识别”作为发布质量控制数据随批次归档并参与完整性校验。
- 每次上传整理包都生成新版本，不覆盖历史整理包。
- 只有最新且校验通过的整理包可以提交终审。

### 2.3 同步人员：生产发布

- 只能同步已经终审通过的最新整理包。
- 同步人员不能代替审核人员完成终审。
- 同步前必须展示并确认生产数据差异摘要，特别是删除量和异常下降比例。
- 同步采用单事务快照替换；失败时生产数据保持原状。

## 3. 状态机

```text
VALIDATION_FAILED  文件结构或数据校验失败，结束
PENDING_REVIEW     普通上传者已提交，等待初审
REVISION_REQUIRED  初审退回；必须填写原因，上传者重新提交新批次
ENRICHMENT_REQUIRED 初审通过，等待审核人员上传完整整理包
PENDING_APPROVAL   整理包校验通过，等待终审
APPROVED           终审通过，等待同步
SYNCED             已发布到生产数据
SYNC_FAILED        同步失败，可在修复原因后重试
```

不设置“审核中”人工状态。打开详情不改变业务状态，避免审核人员关闭浏览器后形成无主锁。若以后审核团队扩大，再增加领取和转交任务。

## 4. 必要审核项

终审必须逐项确认：

1. 原始提交数据已经包含在完整整理包中；
2. 文献编号、DOI和来源行可以追溯；
3. 关键数值与单位已检查，阻断错误为零；
4. 点位关联和跨文献合并依据已检查；
5. ICD11 映射层级与“不入图原因”已检查；
6. 采样方法标准化和原文证据已检查；
7. 核心标记物评分表由规定脚本生成，异常检查已处理；
8. 生产差异摘要已经查看并接受。

驳回/退回原因必须填写。终审备注可选。

## 5. 自动化保护

- 文件扩展名、空文件、50MB 上限、Excel 可读性和目录安全沿用现有规则。
- 提交文件和整理包分别计算 SHA-256；相同文件不得无提示重复上传。
- 整理包必须版本化保存，数据库只记录受控根目录内的规范化路径。
- 比较提交文件和整理包中“数据表”的稳定行指纹，缺失任何提交行均阻断终审。
- 生成按工作表统计的“当前生产行数 / 拟发布行数 / 增减量 / 减少比例”。
- 生产已有数据时，若关键业务表减少超过阈值，必须由管理员额外确认，不允许静默发布。
- 所有初审、整理包上传、终审、同步和失败事件写入操作日志。

## 6. 当前阶段不增加的功能

- 不要求对两万多行数据逐行点击通过；
- 不设置三级以上审批；
- 不在第一版增加电子签名和会签；
- 不允许在网页中直接编辑全部 Excel 单元格；
- 不删除任何历史提交文件、整理包或审核记录。

这些功能会显著增加操作成本，但对当前单服务器、小审核团队的风险收益不高。

## 7. 测试与生产数据恢复

端到端测试使用参考汇总表按文献编号切出的最小闭合集：

1. 备份测试前数据库并记录关键表行数和校验值；
2. 从完整汇总表切出少量文献及其数据表、点位、ICD11、文献、采样审计和核心标记物关联行；
3. 验证提交、初审、整理包、终审、同步、退回、重复上传和异常回滚；
4. 恢复数据库备份；
5. 再次核对关键表行数和校验值，确认与测试前一致。

若恢复核验失败，不得把该环境标记为可交付。
